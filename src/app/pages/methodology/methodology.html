Methodology Runtime telemetry

From runtime telemetry
to LLM-driven decompositions

Java repositories were instrumented and exercised through their existing test suites to collect runtime telemetry. The resulting traces were used to derive behavioral models; each model was then added individually as the final artifact in the LLM input. This process was repeated for every repository and model variant, producing the decompositions shown in Results.

Research question

How do microservice decomposition results change when one runtime-derived behavioral model is appended to the baseline LLM input, across repositories and model-generation approaches?

Inside steps 01–02

How runtime data was collected

First, each repository was instrumented with the OpenTelemetry Java Agent[1]. Its application was then executed automatically and systematically with the tests already present in the repository.

The OpenTelemetry Java Agent[1] was attached to each application. Its standard configuration does not capture method parameter values, so a custom extension intercepted method calls and recorded parameter values alongside the traces.

The repositories use different Java versions, so multiple compatible implementations of the custom extension were developed. During each test run, the OpenTelemetry Collector received the instrumented telemetry and generated the three output files below.

Inside step 03

From execution traces to behavioral models

Generation used two independent approaches. First, the GK-Tail+ algorithm [2] learned an Extended Finite State Machine (EFSM) from the traces and captured method parameters. Then PM4Py [3] analyzed the same traces.json as an event log to discover three process models; it did not use the EFSM as input.

Model representations

Graphviz and Mermaid

Each generated model has a textual specification and a graphical representation in both Graphviz and Mermaid. These textual specifications are the model artifacts later added to the LLM input.

Some models were too large for free online editors to render as images. As a result, some graphical images are missing even where the textual specification exists.
